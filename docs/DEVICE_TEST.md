# Физическая проверка / Physical qualification

Статус: полная приёмка НЕ ПРОВЕРЕНА. Пользователь протестировал0.1.0 на Pixel10Pro CP41.260831.007.A3 с AirPods5: режимы переключаются, заряд и popup отсутствуют. Это частичное пользовательское наблюдение, без захвата пакетов и проверки всего чеклиста. Телефон отдельно от Mac; для повторного теста опубликован0.1.1 diagnostics.

Для каждого Pixel10Pro/11Pro и каждой stable/beta сборки отдельно запишите: модель, точный Build ID, Google Play system update, модель AirPods и прошивку. Не публикуйте MAC, полные серийные номера или сырой дамп.

1. Системное спаривание двойным тапом по передней части кейса. Запустить AirMode, Bluetooth разрешить; уведомления сначала отклонить.
2. Открытый кейс и оба наушника в ушах: сравнить все три процента с независимым показанием; неизвестное —.
3. Каждый из четырёх режимов из приложения: записать подтверждённый mode и фактическое слышимое изменение. Отсутствие ACK должно закончить loading≤1.5s и показать ошибку.
4. Добавить плитку, проверить выбранный цикл, синхронизацию с приложением. Переключить ножкой; UI/плитка обновляются≤2s без обратной команды.
5. Подключить заново: ровно один тихий нативный popup для подтверждённой поддерживаемой модели; неизвестный заряд—. При поступлении батареи обновить ту же карточку в пределах исходных8s, не продлевать время и не восстанавливать карточку после ручного закрытия. При отключении убрать живое уведомление, остановить сервис≤30s.
6. Bluetooth выкл/вкл, звонок при смене режима, закрытый удалённый кейс>2min, один наушник в кейсе.
7. Сопряжённые две пары, переименованная пара: проверить выбор и отсутствие смешивания BLE данных.
8. AirPods4 безANC и сторонние наушники: никакие пакеты listening mode не уходят; кнопки/плитка недоступны.
9. Убить процесс, нажать плитку; перезагрузка с подключённой парой при autostarton и off.
10. Нет INTERNET/location/microphone permissions; мобильный трафик пакета0. Заряд и плитка работают при отказе POST_NOTIFICATIONS.
11. Pixel8 cold start до main<1s: измерить на реальном устройстве, не по времени эмулятора.

Pass требует фактические результаты, не галочки из документации. Собранный APK не заменяет этот чеклист.

## Повторный тест0.1.1 по обнаруженному дефекту
Установите `AirMode-0.1.1-diagnostics.apk` из [Release](https://github.com/andrewkazavchinskyy-cloud/AirMode/releases/tag/v0.1.1) поверх текущей версии; подпись та же. Переподключите AirPods, откройте кейс рядом и подождите15s. Отметьте реальные Л/Кейс/П и появление карточки. Затем Настройки →7 нажатий на версию → Отправить; передайте текст отчёта. Отдельный Test popup проверяет нативное отображение на явно демонстрационных80/54/76%, не квалифицирует батарею. Нормальный release не содержит диагностического отчёта.

Диагностический результат должен различить: батарейный пакет отсутствует; пакет приходит и отвергнут строгим парсером; компоненты неизвестны по статусу; нет достоверного соответствия BLE-адреса; popup выключен/разрешение или канал заблокированы. Ни один исход не разрешает придумывать проценты или привязывать чужую пару по RSSI.
