# Физическая проверка / Physical qualification

Статус: 0.2.0 выпущен как стабильный по запросу пользователя после его успешного теста AirPods и заряда Sony. Полная аппаратная матрица остаётся открыта. Последний0.1.2 отчёт Pixel10Pro CP41.260831.007.A3 / SDK37 / AirPods5 A3532 подтверждает Л17%, П31%, кейс недоступен (AAP status4/00), входящие режимы1/2/3/4. Adaptive пришёл через1807ms, после старого1500ms timeout; пользователь сообщает, что остальное работает хорошо. Popup показан через469ms после выбора пары по временам отчёта. Это не проверка независимой точности батареи, всех моделей или акустического поведения. Телефон отдельно от Mac.

Для каждого Pixel10Pro/11Pro и каждой stable/beta сборки отдельно запишите: модель, точный Build ID, Google Play system update, точную модель наушников Apple/Sony и прошивку. Не публикуйте MAC, полные серийные номера или сырой дамп.

1. Системное спаривание способом конкретной модели (двойной тап по передней части кейса относится к AirPods4/5). Запустить AirMode, Bluetooth разрешить; уведомления сначала отклонить.
2. TWS: открытый кейс и оба наушника в ушах, сравнить доступные Л/П/Кейс с независимым показанием. Max/полноразмерные Sony: одно реальное число. Неизвестное —.
3. Каждый доступный модели режим из приложения (четыре для новых ANC AirPods, три для Pro1/Max1 и поддержанных Sony; без ANC кнопок нет): записать подтверждённый mode и фактическое слышимое изменение. Loading≤1.5s; нейтральное ожидание до2.5s, затем ошибка, если подтверждения нет. Старый1500ms предел ошибки заменён по реальному отчёту.
4. Добавить плитку, проверить выбранный цикл, синхронизацию с приложением. Переключить ножкой; UI/плитка обновляются≤2s без обратной команды.
5. Подключить заново: ровно один тихий нативный popup для подтверждённой поддерживаемой модели; неизвестный заряд—. При поступлении батареи обновить ту же карточку в пределах исходных8s, не продлевать время и не восстанавливать карточку после ручного закрытия. При отключении убрать живое уведомление, остановить сервис≤30s.
6. Bluetooth выкл/вкл, звонок при смене режима, закрытый удалённый кейс>2min, один наушник в кейсе.
7. Сопряжённые две пары, переименованная пара: проверить выбор и отсутствие смешивания BLE данных.
8. Модели без управления/неподтверждённые наушники: никакие пакеты listening mode не уходят; кнопки/плитка недоступны.
9. Убить процесс, нажать плитку; перезагрузка с подключённой парой при autostarton и off.
10. Нет INTERNET/location/microphone permissions; мобильный трафик пакета0. Заряд и плитка работают при отказе POST_NOTIFICATIONS.
11. Pixel8 cold start до main<1s: измерить на реальном устройстве, не по времени эмулятора.

Pass требует фактические результаты, не галочки из документации. Собранный APK не заменяет этот чеклист.

## Архив: повторный тест0.1.2 по реальному отчёту
Эти инструкции относятся к старой0.1.2, когда использовался `AirMode-0.1.2-diagnostics.apk` из [архивного Release](https://github.com/andrewkazavchinskyy-cloud/AirMode/releases/tag/v0.1.2). Не устанавливайте его поверх0.2.0: Android запрещает понижение versionCode. Для текущего приложения используйте diagnostics0.2.0 и актуальный чеклист ниже. Переподключите AirPods, откройте кейс рядом и отметьте задержку появления карточки и новые Л/Кейс/П. При закрытом недоступном кейсе ожидайте— с отдельно подписанным последним значением, не прежний процент как текущий. Выньте оба наушника, выберите Adaptive и проверьте фактический звук и входящий mode4; заявленный режим без ответа недопустим. Проверьте отсутствие неожиданного изменения звука при разговоре после объявления возможностей сессии. Затем Настройки →7 нажатий на версию → Отправить; передайте текст отчёта. Отдельный Test popup проверяет нативное отображение на явно демонстрационных80/54/76%, не квалифицирует батарею. Нормальный release не содержит диагностического отчёта.

Диагностический результат должен различить: батарейный пакет отсутствует; пакет приходит и отвергнут строгим парсером; компоненты неизвестны по статусу; нет достоверного соответствия BLE-адреса; popup выключен/разрешение или канал заблокированы. Ни один исход не разрешает придумывать проценты или привязывать чужую пару по RSSI.

Добавьте новый виджет через настройки AirMode: проверьте все четыре прямые кнопки и их синхронизацию с приложением/плиткой. После убийства процесса нажмите режим на сохранённом виджете; перед записью должны заново подтверждаться connected и поддерживаемая ANC-модель. При отсутствии разрешения виджет открывает приложение.

## Повторный тест0.2.0

1. Установить same-key diagnostics из [Release0.2.0](https://github.com/andrewkazavchinskyy-cloud/AirMode/releases/tag/v0.2.0) поверх0.1.2. Переподключить AirPods, открыть кейс рядом и нажать «Обновить заряд»; следующий скан возможен через15s. Сравнить кейс с независимым источником при открытии/закрытии/зарядке.
2. Отчёт должен показать факт получения proximity keys, matched/accepted BLE и encrypted-case counts. Ключи/адреса/cipher не публиковать. Если кейс остаётся—, прислать безопасный отчёт: это означает отсутствие известного достоверного источника, не разрешает подставить100%.
3. Прогнать Adaptive/Off/Transparency/ANC: реальный ответ в1.5–2.5s не должен давать ложную ошибку. Проверить прямые кнопки обновлённого виджета, холодный старт команды и режим с ножки.
4. Проверить AirPods1–3/4nonANC батарею без кнопок; Pro1/Max1 только три режима; Pro2/3/Max2 доступные четыре. Max показывает одно число, без фиктивных Л/П/Кейс.
5. Sony: записать точную модель/firmware, закрыть Sound Connect, переподключить. Подтвердить live service/version/model/capabilities, реальные отдельные/общие батареи и доступные режимы. Проверить реальное аудио, RET/NOTIFY, отсутствие изменения громкости/эквалайзера/других настроек и акустических побочных эффектов. Проверить задержанный ACK/retry/reconnect. Пользователь подтвердил заряд Sony, точная модель не указана; режимы и независимая точность требуют результатов для конкретной модели.
6. Unknown Sony/firmware и посторонняя пара рядом должны оставаться без неподтверждённых команд/чужого заряда. Конкретные непройденные схемы документировать как ограничения, а не универсальную поддержку.

0.1.2 инструкции выше сохранены как история; актуальный retest —0.2.0. Тестовые дизайн-скриншоты/эмулятор не заменяют эти пункты.
